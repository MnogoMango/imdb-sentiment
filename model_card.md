### Архитектура

Пайплайн состоит из трёх шагов (`model.py`). Очистка включена в сам `Pipeline`, поэтому при обучении и при инференсе тексты обрабатываются одинаково.

| Шаг | Компонент | Параметры (`configs/default.toml`) |
|---|---|---|
| `clean` | `FunctionTransformer(clean_texts)` | Удаляет HTML-теги, раскрывает HTML-сущности, сжимает пробелы; регистр, пунктуация и отрицания сохраняются |
| `tfidf` | `TfidfVectorizer` | `ngram_range=(1, 2)` (униграммы и биграммы), `min_df=2`, `max_features=100000`, `sublinear_tf=true`; приведение к нижнему регистру выполняется векторизатором по умолчанию |
| `classifier` | `LogisticRegression` | `C=1.0`, `max_iter=1000`, `random_state=42` |

Решение принимается по максимальной вероятности класса (`argmax`), что для двух классов соответствует порогу 0.5.

### Воспроизводимость

При обучении сохраняются: SHA-256 хэш датасета (`dfc44776…95aa2`), конфигурация, размеры и индексы выборок (`split_indices.json`), версии библиотек, дата создания и отчёт об аудите данных (`audit.json`). При загрузке модели проверяются схема артефакта и версия `scikit-learn`; тестирование отказывается работать, если датасет отличается от обучающего. Во время обучения предупреждение о несходимости (`ConvergenceWarning`) трактуется как ошибка.

## 2. Intended Use (Назначение)

**Основное назначение.** Автоматическое определение тональности (негативная / позитивная) англоязычных отзывов на фильмы.

**Целевые пользователи.** Аналитики и разработчики, которым нужна быстрая и интерпретируемая базовая модель для оценки настроений в отзывах; участники учебного проекта по MLOps.

**Допустимые сценарии:**
- пакетная или онлайн-разметка тональности отзывов о фильмах;
- baseline для сравнения с более сложными моделями (например, трансформерами);
- демонстрация воспроизводимого ML-пайплайна (аудит данных → обучение → валидация → тест → инференс).

**Недопустимые / неподходящие сценарии:**
- тексты не на английском языке;
- отзывы о товарах и услугах, посты из соцсетей, новости и другие домены, отличающиеся от киноотзывов, без дополнительной проверки качества;
- автоматические решения, влияющие на людей (найм, кредитование, модерация с блокировками) без участия человека;
- анализ сарказма, иронии, смешанных оценок и нейтральной тональности (модель различает только два класса).

## 3. Factors (Факторы, влияющие на качество)

- **Язык и домен:** обучение только на английских отзывах IMDB; вне этого домена качество ожидаемо снижается.
- **Длина текста:** в обучающих данных отзывы содержат в среднем около 229 слов (медиана 171, от 4 до 2 459). Очень короткие тексты содержат мало признаков; длинные отзывы часто включают смешанные оценки.
- **HTML-разметка:** 58 % исходных отзывов (29 202 из 50 000) содержат HTML-теги (в основном переносы строк); именно поэтому очистка встроена в пайплайн.
- **Лексика:** модель опирается на униграммы и биграммы, поэтому плохо учитывает порядок слов на большом расстоянии, сарказм и контекст.
- **Слова вне словаря:** слова, не вошедшие в словарь (`min_df=2`, `max_features=100000`), игнорируются; опечатки и сленг обрабатываются как неизвестные признаки.
- **Разметка:** метки взяты из исходного датасета и могут содержать шум.

## 4. Metrics (Метрики качества)

| Метрика | Почему выбрана |
|---|---|
| **Accuracy** | Основная метрика; классы в датасете сбалансированы (25 000 / 25 000), поэтому доля верных ответов информативна |
| **Macro F1** | Усредняет F1 по классам `negative` и `positive`; показывает, нет ли перекоса в качестве между классами |
| **Precision / Recall / F1 по классам** (`classification_report`) | Показывает, какой из классов модель распознаёт хуже |
| **Confusion matrix** (`*_confusion.png`) | Наглядное распределение ошибок FP/FN |

Дополнительно сохраняется файл со всеми ошибочными предсказаниями (`*_errors.csv`) для ручного анализа.

**Порядок оценки:**
1. Модель обучается только на выборке `train`.
2. При обучении оценивается только `validation` (`validation_metrics.json`).
3. Выборка `test` используется отдельной командой `test` (`test_metrics.json`), что исключает подбор параметров по тестовым данным.

## 5. Training Data (Обучающие данные)

| Параметр | Значение |
|---|---|
| Источник | IMDB Dataset of 50K Movie Reviews (`data/IMDB Dataset.csv`), публичный датасет |
| Поля | `review` — текст отзыва, `sentiment` — метка (`positive` / `negative`) |
| Исходный объём | 50 000 отзывов; классы сбалансированы: 25 000 positive и 25 000 negative |
| Аудит данных | Пустых отзывов — 0, пропущенных меток — 0, недопустимых меток — 0, противоречивых дубликатов — 0, лишних дубликатов — 422, отзывов с HTML — 29 202 (`audit.json`) |
| Очистка | HTML-теги удаляются, HTML-сущности раскрываются, пробелы сжимаются; регистр, пунктуация и отрицания сохраняются |
| Удаление дубликатов | Дубликаты определяются по очищенному тексту без учёта регистра (`casefold`); остаётся первая запись. Если у одинаковых текстов разные метки, подготовка данных завершается ошибкой |
| Строгая проверка | Пустые отзывы, пропуски и недопустимые метки приводят к ошибке, а не к тихому удалению или перемаркировке |
| Кодирование меток | `negative` → 0, `positive` → 1 |
| Размер после подготовки | 49 578 уникальных отзывов (50 000 − 422) |

**Разбиение (`split_data`, `SplitConfig`):**

| Выборка | Доля | Размер |
|---|---|---|
| Train | 80 % | 39 662 |
| Validation | 10 % | 4 958 |
| Test | 10 % | 4 958 |

Разбиение стратифицированное (сохраняет пропорцию классов), выполняется с `random_state=42` и **после** удаления дубликатов, поэтому один и тот же отзыв не попадает одновременно в обучающую и оценочную выборки (нет утечки данных). Индексы выборок сохраняются в `split_indices.json`.

## 6. Evaluation Data (Данные для оценки)

- **Validation** — 4 958 отзывов (10 %), не участвующих в обучении; используется при разработке и сравнении вариантов модели.
- **Test** — 4 958 отзывов (10 %), формируемых тем же детерминированным разбиением; при тестировании разбиение восстанавливается из конфигурации, сохранённой в артефакте, а совпадение датасета проверяется по SHA-256.
- Оценочные данные происходят из того же источника и домена, что и обучающие, поэтому оценка отражает качество **внутри домена IMDB**, а не на произвольных текстах.

## 8. Inputs and Outputs (Вход и выход)

**Вход:** список непустых строк (`list[str]`) — тексты отзывов на английском языке. Пустые строки (в том числе состоящие только из пробелов или HTML-тегов) и не-строки приводят к `ValueError`.

**Выход:** для каждого текста — объект:

```json
{
  "text": "A wonderful movie with excellent acting.",
  "sentiment": "positive",
  "positive_probability": 0.9593
}
```

- `sentiment` — `negative` или `positive`;
- `positive_probability` — оценка вероятности положительного класса (0…1); не гарантируется как строго откалиброванная вероятность.

**Пример вызова и результат:**

```bash
poetry run python -m imdb_sentiment.cli predict --model ".\artifacts\run-001\model.joblib" --text "A wonderful movie with excellent acting." --text "A boring movie and a complete waste of time."
```

| Текст | sentiment | positive_probability |
|---|---|---|
| A wonderful movie with excellent acting. | positive | 0.9593 |
| A boring movie and a complete waste of time. | negative | 0.0094 |

## 9. Ethical Considerations (Этические аспекты и риски)

- **Смещения данных.** Отзывы написаны определённой аудиторией IMDB; модель может хуже работать с диалектами, стилями и темами, нетипичными для этой выборки.
- **Персональные данные.** Датасет состоит из публичных отзывов; при применении к собственным данным нужно убедиться в отсутствии персональной информации и соблюдении правил её обработки.
- **Ответственность.** Предсказания модели — вспомогательный сигнал. Для решений с последствиями для людей необходим контроль человека.
- **Безопасность загрузки.** `joblib` использует `pickle`: загружать артефакты следует только из доверенных источников (это отмечено в коде).

## 10. Caveats and Recommendations (Ограничения и рекомендации)

**Ограничения:**
- только два класса, нейтральная тональность не выделяется;
- плохо распознаёт сарказм, иронию и сложные конструкции с отрицанием;
- учитывает только локальный контекст (до биграмм), без анализа смысла всего текста;
- качество (около 91 % accuracy) проверено только на домене киноотзывов на английском языке;
- небольшой перекос ошибок: отрицательные отзывы чаще ошибочно получают метку positive;
- артефакт привязан к версии `scikit-learn`, использованной при обучении (1.8.0);
- набор данных очищается строго: при противоречивых метках у одинаковых текстов пайплайн останавливается, а не исправляет данные автоматически.

**Рекомендации:**
- при смене домена или языка — заново обучить и проверить модель на размеченных данных нового домена;
- для сомнительных случаев (вероятность около 0.5) направлять текст на ручную проверку;
- периодически переоценивать качество на свежих данных (мониторинг дрейфа);
- для более высокого качества сравнить с моделями на базе трансформеров, используя текущую модель как baseline;
- запускать код в окружении, зафиксированном в `poetry.lock`.
